Website interface research

Look closer at the web.

Exploring how automation and AI can help identify dark patterns in website interfaces.

DarkSense AI is a project focused on collecting website interface evidence and investigating approaches for detecting potentially deceptive design patterns. The work discussed so far includes Python-based collection, Selenium browser automation, preparation of labeled text data, a BERT text-classification experiment, and an EfficientNet preprocessing and inference pipeline.

Project focus

Interfaces can influence decisions.

The project examines website UI and text for signals that may warrant closer review. A detected signal needs context; it is not, by itself, proof of intent.

  • Browser automation with Selenium
  • Website and screenshot collection
  • NLP exploration for dark-pattern text
01 / About

Make the interface easier to question.

Dark patterns are design choices that can steer people toward decisions they might not otherwise make. DarkSense AI explores ways to surface potentially relevant interface behavior so it can be inspected more carefully.

02 / Approach

Collect evidence first. Interpret it carefully.

Collection, text classification and visual analysis are separate workstreams; the complete pipeline is not presented as a deployed service.

STEP 01

Collect

Use Python-based collection and Selenium to visit pages, extract visible text, capture screenshots, and handle dynamic-page failures. An earlier HTMLParser-based extraction approach was also discussed.

STEP 02

Prepare and analyze

Prepare labeled text samples for binary classification, then train and evaluate a BERT-based NLP model. EfficientNet preprocessing and inference using PyTorch were also discussed for visual analysis; full multimodal integration is not verified.

STEP 03

Review

Inspect potential signals in context rather than treating an automated prediction as a definitive conclusion.

03 / Implementation

From website evidence to model experiments.

A closer look at the work: website collection, the BERT experiment, and visual-analysis exploration.

01COLLECTION

Browser-based inspection

Python and Selenium were used in the collection workflow discussed previously. The work included URL crawling, extracting page text, taking UI screenshots, and handling dynamic pages and crawl failures. HTMLParser was part of an earlier text-extraction approach.

02NLP EXPERIMENT

BERT text classification

The NLP experiment used bert-base-uncased with Hugging Face Transformers. The workflow covered labeled binary data preparation, tokenization, training, saving the model, inference, and evaluation using precision, recall, F1 score and a confusion matrix.

03VISUAL EXPLORATION

EfficientNet pipeline

An EfficientNet preprocessing and inference pipeline using PyTorch was discussed for visual analysis. The broader design also considers heuristic signals such as urgency wording, scarcity claims, countdown timers and misleading discounts.

Engineering considerations

The work also involved practical crawler concerns such as explicit waits, exception handling, retries, checking for missing elements and per-URL logging. The integration discussions covered multimodal fusion and end-to-end reliability. These are distinct from claiming that every component is already integrated and deployed.

05 / Scope

Clear about what is—and isn't—here.

This page is a static project overview. It does not accept URLs for scanning, call a detection API or display live model results.

The project notes contain reported data-collection figures and an NLP accuracy result, but those metrics are intentionally omitted here because they have not been independently reproduced or tied to a verified current implementation.

The page documents the work completed and the direction explored so far, without implying that a live scanner is available.
