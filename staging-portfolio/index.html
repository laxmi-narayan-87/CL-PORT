05 / Quality & security

Quality should be observable.

Useful test evidence records what was exercised, under which conditions, and what happened—not just which tools were used.

Testing principles

  • Group test cases by feature and user journey
  • Cover boundary conditions, invalid input, empty states, and permission scenarios
  • Record expected versus actual behaviour with reproducible steps
  • Include test output and environment details
  • Distinguish implemented, tested, and planned work

Security principles

  • Check source and history for exposed secrets, keys, and personal identifiers
  • Use least-privilege access and keep privileged secrets on the server
  • Validate untrusted inputs and avoid unsafe DOM insertion
  • Use HTTPS and restrictive response headers in deployment
  • Review dependencies and run relevant checks before release
